# Data handling

Version 0.4 uses local PowerShell and built-in .NET. Its bundled CSV/JSON helper is compiled locally by `Add-Type`; no package feed, external module or Python runtime is called. It does not change execution policy. Workstation policies must permit the scripts and local compilation. UTF-8 is decoded strictly; CSV quoting, native types and duplicate JSON keys are checked before a run is written. Read-only workbook inspection uses ZIP/XML with DTD processing disabled and bounded archive size, and leaves the original bytes unchanged. `-ConfirmReviewed` records an operator statement; the inspector cannot establish Microsoft origin or price accuracy by itself. The browser adapter and its requests are unchanged.

Version 0.3 folder ingestion reads only selected `.csv` files, rejects ambiguous/repeated file identities and symbolic-link inputs, and validates all files before creating a run. Per-file names, hashes and row numbers remain local in the job/manifest and appear in the optional browser report. Multi-file custom names sent to Microsoft contain the relative source filename, source group and line ID, so choose filenames suitable for the estimate's audience. Notes stay local.

The CLI reads local CSVs and writes ignored local run artifacts. The browser script sends resource configuration only to Microsoft's official calculator origin through the page's native frontend action. Catalog preflight explicitly omits credentials. Native page pricing/load/export requests use the browser's ordinary behavior; the script does not inspect or export cookies, tokens, authentication headers or cookie databases.

Generated `import.js`, job JSON, source labels, reports and Excel workbooks can contain customer data. Keep them in ignored `runs/` and share only after review. Notes remain local in job JSON. Console diagnostics contain only error messages; no complete payloads or headers are logged.

The import asks once to create or resume one tool-owned estimate. It does not invoke account Save, Share, Delete or clear browser storage. Other estimates are retained. Source groups are metadata; loading chunks share the same estimate ID. Ownership and configuration checks stop changes if another estimate is active, resources were manually changed, or module IDs/counts differ from the checkpoint.

Only the tool's own `calcbridge:v2:` localStorage namespace is written directly. Checkpoints contain the job configuration hash, pinned deployment, estimate ID, planned module IDs and committed/pending counts. A separate key preserves a server-requested retry time. They contain no credentials or full resource configurations. Microsoft's native frontend actions handle its own persistence; no Microsoft storage keys are written directly. Local browser storage is not a secure vault or an account backup.

Catalog reads retry only transient failures with bounded exponential backoff, jitter and `Retry-After`. During native loading, a temporary fetch wrapper retries only same-origin pricing GETs with their original arguments and restores the wrapper afterward. The importer reconciles an already-committed absolute prefix before retrying a loading step, preserving IDs to avoid duplicates after a lost acknowledgement. Invalid input, schema drift, authentication failures and oversized export requests stop. A long `Retry-After` pauses with a resume time.

Compact export briefly captures the native control's form submission, checks its configuration against the loaded estimate, and removes only the verified unused Premium SSD v2 cache from supported compute-only VMs. It submits to the exact observed Microsoft export endpoint using the normal same-origin browser session. Native Excel generation may retry transient failures; account Save/Share writes are never replayed. The returned workbook is downloaded unchanged. The report records received bytes/hash and a download request; operators still check their completed download and provenance.

The frontend adapter and templates are pinned to a live-tested deployment and schemas. Changes fail closed. Fixture hashes prevent importing a modified template unnoticed. CSV validation rejects formula-like resource labels; exact line names and estimate identity are reconciled in the untouched export. Reconciliation and hashes do not alone establish workbook origin or binding commercial pricing.
